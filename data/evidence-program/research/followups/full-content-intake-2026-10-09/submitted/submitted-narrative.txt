## 3. OpenAlex-linked openly licensed full text

### Enumerable population and legitimate routes

The acquisition unit should be:

**Work → location → exact edition → representation → observed bytes.**

A Work is an organizing identity, not a guarantee of one manuscript edition. OpenAlex documents that a Work can combine preprint and journal locations; its canonical DOI can be the published DOI, and its metadata-update timestamp can change with citation counts. Neither identifies a new manuscript version. [OpenAlex Help Center](https://help.openalex.org/data/works/attributes/?utm_source=chatgpt.com)

For a small tranche, freeze an explicit identifier/query manifest and preserve complete JSON responses. For expansion, record the selected corpus—`core`, `expansion` or `all`—and all filters and exclusions. A snapshot route needs an actual release manifest with its file membership, counts and lengths. **No current snapshot manifest or exhaustive relevant-work population was inspected.**

Native metadata formats are API JSON and snapshot gzip JSONL or Snappy Parquet. OpenAlex also documents cached PDFs and GROBID-derived TEI XML. The cached files require an API key; full archive synchronization requires a paid service and issued credentials. Those services were documented, not exercised. [OpenAlex Help Center](https://help.openalex.org/access/snapshot/?utm_source=chatgpt.com)

### Representative lineage: a consequential identity mismatch

A bounded anonymous request for the preprint DOI `10.48550/arXiv.2401.02843` returned **Work W4414876758**, whose canonical DOI is the JAIR publication `10.1613/jair.1.19087`.

The response was **HTTP 200, 18,977 bytes**, observed at **2026-10-09T15:34:12.583153Z**. The unchanged response and observation receipt are included in the bundle:

- [openalex_W4414876758_observed.json](openalex_W4414876758_observed.json)
- [openalex_W4414876758_receipt.json](openalex_W4414876758_receipt.json)

| Observed location or representation | What the response establishes | Acquisition consequence |
|---|---|---|
| JAIR publication location | `cc-by` label, `publishedVersion`, publisher PDF URL | Publisher’s exact edition/grant was not inspected; hold that body |
| arXiv OAI location | `cc-by`, `submittedVersion`, **unversioned** PDF URL | Resolve an explicit `vN`; do not label this URL v3 |
| arXiv DOI location | Another identifier, with version and PDF URL null | Preserve the identity relation; do not count another original |

The separately inspected **arXiv v3 page** provides an exact version, a pinned PDF link and a CC BY 4.0 article-rights link. That qualifies the direct arXiv candidate; it does not transfer permission or byte identity to the JAIR or cached objects. [arxiv.org](https://arxiv.org/abs/2401.02843v3?utm_source=chatgpt.com)

Accordingly, the cached artifact records have **null origin and license fields**, with the location claims retained as supporting evidence. They do not silently inherit the arXiv grant.

### Rights, limits, updates and deletions

OpenAlex’s metadata is CC0. Its cached PDFs retain their original copyright; OpenAlex grants no additional content rights. GROBID XML is a derivative that can omit content and cannot replace preservation of the complete original. [OpenAlex Help Center](https://help.openalex.org/access/sync/?utm_source=chatgpt.com)

The inspected access documentation specifies a **$0.10/day keyless metadata allowance**, a **100-request/second ceiling**, **100 records per page**, and a **10,000-result basic-pagination limit**. These are documented ceilings, not proposed operating targets. The observed external-DOI request consumed one reported credit, so the specification does not assume it behaves like the documentation’s free exact-ID singleton example. [OpenAlex Help Center](https://help.openalex.org/api/llm-quick-reference/?utm_source=chatgpt.com)

The required lifecycle distinctions are:

- **Metadata changes:** retain changed complete responses without treating every change as a paper revision.
- **Snapshot changes:** the public bucket replaces prior releases, so preserve the actual release identity needed for reproducibility.
- **Cached-object changes:** the documented daily replacement Parquet manifest maps Work IDs to PDF/XML object UUIDs. A publisher URL cannot substitute for that mapping.
- **Deletions:** a missing or merged-away Work ID can return 404 without a survivor redirect. The works deletion file is replacement state, not an append-only event stream. The same documentation describes rare restoration and also calls deletion final; that inconsistency remains explicit. [OpenAlex Help Center](https://help.openalex.org/access/sync/?utm_source=chatgpt.com)

**Unblocking evidence:** qualify the exact primary edition and its grant for direct copies. For cached service intake, additionally establish authorized access, exact object/edition binding, finite membership and capacity. The paid `from_created_date` and `from_updated_date` filters do not establish a keyless incremental-completeness route. [OpenAlex Help Center](https://help.openalex.org/access/sync/?utm_source=chatgpt.com)

### Private research preservation and public serving resolve differently

The current API terms explicitly allow retrieving, storing and using e-print content for personal or research purposes. They separately require applicable permission for public serving.

Therefore, **CN017’s standard arXiv license is not, by itself, a private-research preservation hold**. It remains a public-redistribution hold without an additional applicable grant. Technical access restrictions and component-specific notices still apply. This conclusion does not authorize model training or all downstream uses. [arXiv info](https://info.arxiv.org/help/api/tou.html?utm_source=chatgpt.com)

Licenses can differ across versions. A later permissive license must not be inherited backward, and a version’s license record must remain attached to that edition. [arXiv info](https://info.arxiv.org/help/license/index.html?utm_source=chatgpt.com)

### Native source access remains unresolved

The sampled pages expose exact `/src/...vN` links labeled “TeX Source.” **That label does not establish the actual container, member list, MIME type or bytes.** The eventual reader must detect the submitted representation rather than assume every source is a TeX tarball.

The pinned acquisition manifest records a prior robots inspection that allowed the targeted PDF routes, disallowed `/src` and `/e-print`, and recorded a fifteen-second article crawl delay. **This is dated repository evidence, not a fresh robots inspection.** No source request was made to resolve it. See the pinned [acquisition manifest](https://github.com/mishakgg/pdoom-live/blob/720ee3cb7107cc0cb9bca8b85983df7ee8db6ddc/data/evidence-program/full-content-acquisition.json).

The official bulk overview identifies S3 as the accepted complete-corpus route and rejects complete-corpus programmatic crawling of the web service. However, its linked S3 detail page, manifests, access/payment conditions and historical-version coverage were outside the allocated checks. **“All available articles” was not interpreted as “every historical version.”** [arXiv info](https://info.arxiv.org/help/bulk_data.html?utm_source=chatgpt.com)

For legacy metadata APIs, the documented limit is one request every three seconds and one connection across the operator’s controlled machines. That does not override the separate article/source policy. [arXiv info](https://info.arxiv.org/help/api/tou.html?utm_source=chatgpt.com)

### Deletion boundary and exact unblocking evidence

The permanent-record statement does not establish a full withdrawal or takedown protocol. The specification records withdrawal, access failure and rights changes separately; it does not propagate a version-local withdrawal across the lineage or destroy a permitted original because metadata disappears. [arXiv info](https://info.arxiv.org/help/license/index.html?utm_source=chatgpt.com)

The remaining requirements are narrowly scoped:

- **Native source:** current policy or a supported alternate route resolving the recorded restriction, followed by finite container/size/member and integrity verification.
- **Complete versioned corpus:** an authoritative manifest establishing historical-version membership, legitimate access conditions and update/removal semantics.
- **Automated deletion handling:** current withdrawal/takedown policy and the live OAI deletion declaration.

These gaps do not block reuse of an independently qualified PDF.

## 6. Acquisition specification

The supplied specification uses the following common controls. These are proposed requirements; no collection implementation was exercised.

### Enumeration and identity

Freeze the selection before acquisition, recording exact IDs, filters, corpus, observation interval and exclusions. Keep separate counts for:

- Logical works or datasets.
- Publisher versions.
- Locations and representations.
- Complete retained blobs.
- Incomplete, held and excluded candidates.

Preserve complete native fields, original language and unknown values. For worldwide expansion, do not silently exclude regions or languages, and do not treat a narrow author query or an AI subject category as an exhaustive population.

Deduplicate physical storage by complete SHA-256 and length, while retaining all URL, rights, version and observation relationships. A journal version, preprint revision, mirror, parse and transport package do not automatically add independent scientific coverage.

### Retrieval, retries and commitment

Each source request needs a selected exact URL, applicable rights evidence, current access qualification and a finite transfer ceiling.

The proposed retry policy allows up to five attempts for transient failures, with exponential backoff and jitter. It honors `Retry-After` and quota resets. Long delays are checkpointed for a later retry rather than shortened.

Authentication redirects, explicit policy denials, changed identity, unexpected media types or exceeded size bounds stop the candidate. A 404/410 records an unresolved access event; it does not itself prove deletion.

Partial transfers may resume only with consistent validators, contiguous ranges, stable totals and encoding. **Never concatenate ranges from different versions.** Destination outcomes that are uncertain must reconcile the same transaction before another write.

Commit the retained-object receipt only after whole-byte integrity and raw readback verification. Advance enumeration checkpoints only after the corresponding enumeration unit is complete. Individual complete permitted objects may be retained during a partial backfill without falsely completing that backfill.

### Completeness is multidimensional

| Check | What it establishes |
|---|---|
| Whole-response integrity | The retained bytes constitute the complete response |
| Representation completeness | The complete PDF, CSV or package was retained |
| Native-feature coverage | Required sheets, notes, source files or other native components are present |
| Population completeness | The declared enumeration frame was exhausted |
| Historical completeness | Every version claimed by the selected historical scope is accounted for |
| Analytical readiness | Identities, constructs, denominators and uncertainty are mapped adequately |

Passing one does not imply the others. This is particularly important for MIT exports, OpenAlex TEI and arXiv PDFs without submitted source packages.

## 7. Schema and eight acceptance cases

The schema keeps rights, access observations, content state, hash scope, native coverage, analytical status and publication authorization independent. Unknown versions and sizes remain null. Historical receipt hashes are explicitly distinguishable from fresh measurements.

It allows a complete lawful original with:

- No official publisher revision.
- A timestamp-and-hash snapshot identity.
- Unknown native-feature coverage.
- Pending analytical mapping.
- No authorization to publish.

The outer schema describes **this fixed research review**. Its reusable artifact definition supports future observations; it is not a production collector contract.
