# AI progression statistics and website implementation plan

Prepared 9 October 2026. Status: proposed implementation specification. No application changes, training, new acquisition or public release are part of this packet.

## Recommendation

Build a versioned evidence dashboard first. The verified material already supports useful resource-coverage statistics, published coding-score comparisons and revision diagnostics. It does not yet support a measured global rate of AI progress, a validated future capability forecast or a data-derived p(doom).

Use four separate analytical products: comparable capability observations; cost-adjusted task performance; calibration of resolvable forecasts; and conditional projections of a specified future metric. Keep MLPerf training-system performance in a fifth, separate resource view. Training completion time, model capability, API prices, training FLOP and catastrophic-risk beliefs have different units and meanings.

The highest-value modelling improvement is an admission layer at the individual metric and feature level, followed by simple, leakage-safe baselines. Adding a more flexible learner before resolving identities and information times would increase apparent sophistication without establishing forecasting validity.

## Analysis and display contract

Create a derived analysis sidecar rather than changing the frozen v0.1 record schemas. It references exact record revisions and carries:

- `analysis_id`, method/configuration/code hashes, snapshot ID and output hash;
- source artifact/hash/native pointer, benchmark revision, metric and direction, native unit and transformation;
- exact executed identity when established, provider-label-only status otherwise, requested alias separately from returned identity;
- protocol identity including tasks, split, prompts, tools/scaffold, decoding, harness/judge, inference budget, output set and denominator evidence;
- selected feature IDs and target IDs, measurement-boundary definitions, compute-estimate dependency IDs;
- source publication/first availability, evaluation/generation, dataset `known_at`, review and correction clocks, each with precision and evidence;
- model lineage component, uncertainty class/method, missing reason, inclusion decision and specific failed gates;
- intended claim tier, display scope and independent release/rights decision.

Use claim tiers `published_score_description`, `verified_comparable_change`, `retrospective_prediction`, `prospective_prediction` and `scenario`. These are analysis-sidecar labels, not new canonical record statuses. Stronger tiers do not automatically follow from a valid schema. Admission must be per metric: resolving HumanEval cannot admit MBPP or all snapshots of that model. Compute ancestry and executed-model identity are different relations.

Expose a minimal allowlisted display object; do not send full research rows or preserved native objects to a learner or the browser. Raw rows contain targets, private intake metadata and irrelevant fields. Public build inputs exclude account IDs, private storage receipts, credential/session fields, uploaded-original identifiers and unpublished source bodies. Source permission and analytical eligibility are separate release checks.

Release authorization includes valid existing user authorization covering the action, destination and scope. Do not request repeated approval when that authorization is sufficient and unchanged. Scientific review and rights checks still apply; seek additional authorization only when it is missing or the scope materially changes. This specification does not itself expand authorized publication or deployment scope.

## Comparable capability and cost modelling

For actual capability change, require two measurements with the same task population/protocol and known model-version relationship. Report absolute percentage-point change first. Relative score change and error reduction are optional distinct statistics. An elapsed-time rate requires real measurement/release times and a meaningful common unit. A protocol revision resets the series unless a matched-overlap bridge is fitted and tested on separate overlap observations.

For a future longitudinal study, start with persistence, a training-only recent-slope baseline and a bounded simple trend model within one protocol. A hierarchical model with family effects is a later candidate, not a default rescue for unknown identities. Use log scale only for positive ratio-scale resources or properly defined task-duration metrics. Use bounded-score models for accuracy without reconstructing trial counts from rounded aggregates. Fit nothing to the two EvalPlus correction vintages as a temporal progression series.

Cost-adjusted performance requires the same tasks, success criterion and run configuration plus total token/tool/retry/time accounting. Show observed quality versus total cost per attempted episode and the nondominated observed configurations. Under a stated batch policy, cost per success is total cost of all attempts, including failures, divided by successful episodes. With zero successes the ratio is undefined/unbounded, never zero. Do not substitute API list price for realized billing, provider production cost or training cost.

Compare the cheapest observed configuration meeting a fixed success target, with uncertainty in target attainment. Interpolation and scenario pricing are separately labeled; extrapolation is not an observed frontier. Training compute inferred from the same benchmark must be excluded from the principal compute–performance association. The seven numeric Epoch rows tagged with a Benchmarks method are known flags, not an exhaustive count of all possible circular estimates. Missing method/notes require review.

## Point in time splits and backtesting

1. **Freeze the question and origin.** Specify one metric, target population, horizon, origin schedule and information-time mode. Current-corpus chronology, retrospective published reconstruction and strict dataset-as-known backtests have different labels. Never overwrite `known_at` with a publication date.
2. **Close dependencies before selection.** At origin T, every feature and its source dependency must be available by T; represented human review must meet the chosen review cutoff. Use conservative upper bounds on uncertain availability. Training targets must have been available before fitting. A prospective base-to-plus opportunity requires base/features available by T and T strictly before plus disclosure. Co-publication fails this rule.
3. **Close lineage transitively.** Shared base models, continuations, fine-tunes, quantizations, adapters, aliases, merges and evidenced material distillation links form connected components. Unknown ancestry is held or included in a prespecified sensitivity quarantine, never an invented independent singleton. All snapshots, metrics and translations of the same underlying observation stay grouped.
4. **Keep two validation questions separate.** Forward prediction for a previously observed family may use its genuinely prior releases. Generalization to an unseen family excludes the entire related component from training. Report separate scores; do not present random-row validation as either. A current graph can enforce conservative split isolation without becoming a backdated predictive feature.
5. **Use nested, forward-origin selection.** Fit transforms, imputation and tuning only inside the training partition. Inner validation precedes outer target windows. Purge records whose generation/publication intervals cross an origin; embargo overlapping target windows as required by the target duration. Fix the fold/origin manifest before looking at losses.
6. **Compare on identical cases.** All procedures use the same admissible cohort, horizons, weights and missing-prediction penalties. Report skipped origins, failures and coverage. Archive raw predictions before outcomes, including no-change baselines, and keep corrected target vintages separately from first-release scoring.
7. **Evaluate the intended forecast.** Report MAE/RMSE in native units and family-macro losses for model-score predictions; proper distribution scores and empirical interval coverage for probabilistic predictions. Separate 3-month and 6-month horizon results. A method improving retrospective masked-plus prediction is not thereby validated for future release trajectories.

## Minimum gates and uncertainty

These are claim-specific gates. Proposed new operational floors are explicit product decisions for review, not universal sample-size theorems or power guarantees.

- **Finite descriptive archive view:** one valid value permits showing that value. A displayed paired change requires two comparable values and their identity/protocol evidence. No minimum row count creates representativeness. Report the finite cohort; no nominal population interval is required or justified merely because there are many labels.
- **Existing robustness pilot:** preserve its exact prerequisites: at least 80 admitted distinct model versions, 20 reviewed components, four components per outer test fold, ten components and 30 rows in each inner training partition, at most seven encoded features, at least two varying raw non-base variables, 80% usable activated-size coverage, and three distinct training target values. Five outer and three inner component folds are specified. HumanEval's actual eligible N/F remain unknown. MBPP has at most 60 complete current pairs, so fails the 80-row gate even optimistically. Do not shrink the gate or restore A scores into B to obtain a fit.
- **Robustness uncertainty and decision:** archive results use per-family errors, component/fold spread and leave-one-family influence, without ordinary CV confidence intervals. Preserve the registered MLP-P primary procedure and its baseline comparison rather than choosing a winner on outer tests. The later frozen prospective cohort requires at least 20 new families, paired family-bootstrap assumptions, interval half-width at most 1 pp and the protocol's effect criteria. These counts do not guarantee precision or power.
- **New longitudinal forecast study:** before a fit, freeze the target, precision criterion and backtest scheme in a separate amendment. Proposed exploratory floor: at least 12 distinct time points spanning 24 months, at least six valid held-out origins per displayed horizon, at least ten reviewed training components at every origin and 20 distinct reviewed test components overall. Overlapping windows do not become six independent observations; use time blocks and lineage-aware dependence analysis. These floors permit evaluation only. Public predictions additionally require predeclared baseline improvement, acceptable horizon-specific coverage/width and a genuinely untouched validation period. If effective information is inadequate, remain descriptive.
- **Calibration of binary forecasts:** a single eligible resolved case permits a case loss, not a calibration claim. The illustrative dashboard targets of 100 resolved event clusters, 20 in each outcome class and 20 per reliability bin are provisional design targets for a nonrare event mix, not universal requirements or hard bans on exploratory scoring. Review them against event rarity, dependence, forecast horizons and desired precision before implementation. For rare outcomes, do not require observing 20 positives before reporting clearly labeled descriptive Brier loss, matched baseline loss, coverage and uncertainty limitations on eligible cases. A one-class sample cannot establish discrimination or calibration across both outcomes. Never count forecast updates as new events. Fix reliability bins beforehand; sparse bins may be displayed with explicit counts and wide uncertainty or withheld for a stated precision reason. A statement of adequate calibration requires prespecified tolerance and precision; a small Brier score alone is insufficient. Public activation still needs the scientific, rights and release-authorization checks, including applicable existing authorization.
- **Cost/performance and MLPerf:** first require comparable valid runs, complete accounting and the benchmark's prescribed repetitions/aggregation. Do not invent a universal replacement repetition count. A selected set of optimized submissions is not a probability sample of hardware installations. Missing system descriptors, thresholds, scaling context or failure dispositions block the affected comparison.

Separate measurement uncertainty, task/population sampling, model uncertainty and scenario assumptions. Aggregate EvalPlus percentages do not establish task-level paired outcomes: no reconstructed binomial trials, McNemar test or task bootstrap. Conditional nearest-rounding sensitivity is at most ±0.05 pp per one-decimal score and ±0.10 pp per gap only if that rounding convention is true; the convention itself is unverified. Fixed-cohort descriptive medians and revision decompositions need no invented sampling CI.

For genuine task samples with retained outcomes, paired task-family resampling can be appropriate; stochastic runs and model lineages add separate dependence. For future predictions, display distinct 50% and 90% prediction intervals only when produced by the frozen model and evaluated at the displayed horizon. Label intervals conditional on the benchmark/protocol/model-release assumptions; they cannot measure all epistemic uncertainty or convert capability into catastrophic risk.

## Missingness and revision rules

Keep `not_evaluated`, `not_disclosed`, `collection_failed`, `unavailable`, `withdrawn`, `identity_unresolved`, `protocol_incomparable` and `not_applicable` separate in the analysis sidecar. An unknown reason remains unknown. Never replace a score, cost or family count with zero. Never carry an earlier score forward through a withdrawal. Predictor imputation, when permitted by a particular protocol, is training-fold-only with an explicit indicator; targets and base scores are not imputed in the robustness pilot.

Publish complete-case and matched-cohort views with exclusions, and show how attrition changes the result. Include expected versus observed positions only when the expected panel is defined. Retired models are not silently dropped from historical panels. Do not inverse-weight to a world population without known inclusion probabilities. An unknown model price cannot be repaired using an unrelated alias or a later tariff.

## Three feasible first experiments

All three use existing verified artifacts. They are bounded descriptive/measurement experiments that can produce useful website behavior before a forecasting study is eligible. Their small arithmetic checks were reproduced for this plan; no learner, benchmark or provider API was run.

### Experiment 1 Explain apparent progress caused by archive revisions

Input: the two exact retained EvalPlus result bodies and protocol metadata. Unit: the same native label and metric across vintages. Calculate slot revisions, withdrawals, same-label mean differences and composition decomposition separately for every metric. For MBPP+, let C be the 60 labels complete in B and A. Then mean(B,C) − mean(A,all 78) equals [mean(B,C) − mean(A,C)] + [mean(A,C) − mean(A,all 78)]. The terms are +1.9033 pp and +0.9912 pp, totaling +2.8945 pp.

Output: revision waterfall, missingness strip and label-level audit table. Stop after exact reconciliation to all 404 slots and source hashes. Success means every displayed change is classified without calling it a new evaluation or progress rate. Do not attribute the within-label term specifically to test edits versus corrected outputs; the run-level decomposition is unavailable.

### Experiment 2 Show the observed base and plus relationship without a fitted predictor

Input: B's 101 HumanEval pairs and 60 MBPP pairs. Show paired scores, gap distributions and tie-invariant midranks within each fixed cohort. The verified median gaps are 4.9 pp and 10.45 pp; 47/101 and 59/60 respectively have gaps at least 5 pp. That threshold is the study's operational diagnostic, not a general definition of unsafe or unrobust AI.

Add an admission audit using the actual recovered 202 candidate positions: it should return held, unknown eligible N/F and no fit. Stop at descriptive output and gate report. No regression of gap on base as causal evidence, no learned prediction, no rank learned from the full target cohort, no task-level uncertainty and no claim that 161 pairs are independent models. This gives a truthful preview of the later preregistered pilot without pretending its identity gates passed.

### Experiment 3 Audit Epoch resource evidence by method and missingness

Input: the exact-original reparse report and its independently matched full method-count table. The report verifies equality to the retained submitted table; this pass does not need to reacquire the cleaned CSV. Unit: a source row in the 3,626-row archived vintage. Reconcile compute/parameter availability, estimation-method combinations, confidence labels among populated compute cells, and the 12 missing publication dates before proposing any resource trend.

The 39 literal method strings reduce to 27 distinct token-set combinations, including missing, after whitespace trimming and order normalization only. Keep original strings for audit; do not merge genuinely different methods. The combination `Hardware,Operation counting` contains 159 rows after combining the two source orderings. Method-token memberships include 851 Operation counting, 631 Hardware and 87 Reported rows; these overlap and are not additive. Of all rows, 2,182 have no method string. Among the narrower 1,410 rows with populated compute, 132 have no method. The compute-populated confidence strata are 945 Confident, 339 Likely, 125 Speculative and one missing; these are Epoch's source labels, not probabilities or analyst certification.

Output: a resource-evidence matrix, method-combination bars, overlapping-membership warning and a conservative eligibility ledger. Flag the seven numeric-compute rows whose method includes Benchmarks for exclusion from independent compute–capability association; review missing-method and scope-ambiguous rows rather than inventing an estimate. Do not subtract independent marginal exclusions to invent a final eligible cohort. Stop when all categories reconcile to their declared populations, the native-to-normalized method mapping is reversible and every intended plot has an explicit gate.

A later resource chronology can use the exact original already archived, after a verified row-level transform preserves publication dates, training stages, bounds and method classes. Missingness by year and actual method-specific FLOP trend slopes are not available from these marginal counts and remain uncomputed. This experiment uses actual archived source statistics to decide which trend claims are supportable; it does not present acquisition dates or two source revisions as growth.

### Optional illustration Show tariff composition without claiming efficiency

Input: the three reviewed R1 advertised rates, preserving their category and unresolved effective interval. With input I, output O and cache-hit share h, the illustrative token quote is [I × (0.14h + 0.55(1−h)) + 2.19O] / 1,000,000 USD. Workloads are explicitly hypothetical, not collected task runs.

Use a fixed grid I=1,000, O in {250, 1,000, 4,000}, h in {0, 0.5, 1}. For I=O=1,000, the quote ranges from USD 0.00233 at all-hit input to 0.00274 at all-miss input. Output length can dominate the quote. Output: nine-cell sensitivity view and exact assumptions. Stop after arithmetic/category checks. No billed-cost claim, tariff timeline, performance ranking, fixed-performance frontier or extrapolated savings is justified. Real cost-adjusted performance remains held until observed workload and identity bindings exist.
